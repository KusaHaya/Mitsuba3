# 再構成した照射像モデル v2（2026-11-20）

`configs/rebuilt_v2.json`が今回の基準。`rebuild_model.py`は計画・実行・共有用ZIP作成をまとめる。物理的な配置を変えず、境界を飛び越える数値問題を避ける座標系と、小さい評価範囲を使う。

## 物理条件

|項目|値|
|---|---|
|レンズ・受光面全体|546×312 mm|
|レンズ周期／曲率半径／屈折率|0.7 mm／0.5 mm／1.49|
|レンズ基板厚／接触したLED側アクリル|2 mm／10 mm|
|傾き|縦からatan(1/3) ≈18.435°|
|LED本数／位相の本数|19本／5・5・5・4本|
|LED幅／発光長|水平3 mm／約328.877 mm|
|LED間隔|溝に直角23.5 mm、水平24.771175 mm|
|LEDからレンズ頂点|138.13 mm|
|レンズ頂点からスクリーン|PMMA中1.5 mmで固定|
|仕切り|高さ32 mm、厚さ1.5 mm、隣接LEDの中間|
|比較条件|仕切りのみ／仕切り＋中央開口率40%マスク|
|スクリーン後方アクリル|5 mm。以前の7 mm推奨は採用しない|
|ディスプレイ内部|背面側ガラス1 mm、n=1.5と仮定|
|観察距離|液晶面から800〜1200 mm|
|眼間距離|65 mmと仮定|

スクリーン後方の層・観察者条件は`observer_evaluation`の投影用メタデータ。今回の描画はスクリーン位置の理想受光面までで、物理的な拡散スクリーン・LCDスタック・液晶応答・観察者までを描画していない。単独LEDで修正後に確認された幅約0.03 mmは中央の局所結果であり、全画面・全位相の保証ではない。

## 数値座標

`render.scene_scale=1000`、`origin_mode=view_center`を使う。Mitsubaの数値座標は1単位がおおよそ1 mmになり、各撮影位置の中心を原点へ移す。カメラだけでなく、LED・レンズ・仕切り・受光面・前方PMMAも同じ量だけ移動する。世界座標での相対配置は維持し、画像に付ける座標は元の物理座標へ戻して表示する。

画面端では座標値そのものが大きくなり、スケール補正だけでは光線の開始位置補正が再び細かな間隔を超える場合がある。回帰テストで、右側の代表的な溝ではglobal原点だと曲面を飛ばすが、view_center原点では曲面を通ることを確認する。

各タイルで全形状の原点を正しく作り直すため、以前の「同一シーンのカメラだけを移動する」方法は使わない。撮影枚数が多い場合はシーンの準備時間が増えるが、光学境界の正しさを優先する。すべての光線・あらゆる接触点での収束を保証するものではない。必要な条件ではscene_scaleを増やす数値安定性の確認も行う。

## 最初の8計算

```powershell
git pull
.\.venv\Scripts\python.exe rebuild_model.py
```

中央2×0.25 mm、512×64画素（0.00390625 mm/画素）、256 spp、GPU、2条件×4位相。各位相に属するLEDをすべて点灯する。10 mmの発光区間へ短縮する診断設定ではなく、19本の実際の長さの光源・全仕切りを保持する。

実行しない計画確認：

```powershell
.\.venv\Scripts\python.exe rebuild_model.py --plan-only
```

中央を確認後、中央と左右各1か所を比較する場合：

```powershell
.\.venv\Scripts\python.exe rebuild_model.py --all-positions
```

評価中心はWorld x=0,-250,+250 mm、y=0。全24計算。各2 mm幅の小範囲であり、その間を連続走査したものでも、全画面の高さを検証したものでもない。LEDは19本のままで、端の暗い位相を便宜的に明るく補正する処理はない。

GPUメモリが不足する場合のみ`--samples-per-pass 1`を追加。同時サンプル数だけ減らす。総spp・光学条件は維持する。

## 保存・再開

完了時に表示する`rebuilt_results.zip`を共有する。設定、照射像の元NPY、個別PNG、プロファイル、CSVを含む。`summary_bundle.zip`だけでは元画像がないため、この小規模実行では元画像込みを推奨する。

中断後は同じオプションを付けて、元の結果フォルダを指定：

```powershell
.\.venv\Scripts\python.exe rebuild_model.py --resume results/生成されたフォルダ名
```

`--all-positions`等を使った場合は再開時も同じにする。設定・モデルの版が一致しない再開は拒否する。旧版の結果は新しいデータとして混ぜない。

## 評価の意味

`metrics.csv`の幅は周期平均した主要ピークの推定値。像が暗い・多峰・ノイズ過多の場合、最大ピークだけを拾うので確定値としない。NPYで個々の縞の幅・位置・暗部も確認する。

`overlap.csv`は異なる時間位相の照射分布の形の重なり。液晶を通して反対の目へ漏れる実機クロストーク率ではない。以前の不具合を含むデータから得た約25%や距離最適化の結論は再利用しない。
