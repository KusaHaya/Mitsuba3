# 連続する高解像度画像での比較

`scan_tiles.py`は全体の光学モデルを維持して、仮想カメラだけを移動する。LED19本、546×312mmの受光面・レンズ、スクリーン1.5mm、LED→頂点138.13mm、LED側アクリル10mm、仕切り32mmは変えない。

## 範囲と分割

4位相の繰り返し周期は水平99.0847mmだが、4本のLEDが照らす範囲は照射角の分だけ広い。仕切りと光源幅を使った単純な近軸・直線光路の概算では約180mm程度になるため、既定は余裕を持つ200mm幅。散乱や多重反射を含む全光路がこの範囲に収まる保証ではない。

| 比較範囲 | World x | World y（既定） |
|---|---|---|
| 左端 | −273～−73mm | −0.5～＋0.5mm |
| 中央 | −100～＋100mm | −0.5～＋0.5mm |
| 右端 | ＋73～＋273mm | −0.5～＋0.5mm |

1範囲を8×1mmの画像25枚に隙間なく分割。3範囲は一部重なり、中央の横方向全体を覆う。全画面の高さ312mmすべてを細分化する設定ではない。別の高さを調べるときは`--y 100`などで指定する。

- 1枚2048×256画素、0.00390625mm/画素。約0.03mmの像に約7.7画素。
- 仕切りあり／仕切り＋マスク × 4位相 = 1タイル8計算。
- 25枚×3範囲 = 75タイル、合計600計算。
- 全体を1枚の高解像度画像にしないので、同時に持つ画像のメモリを抑えられる。合計計算時間や出力容量は小さくならない。NPYだけで約1.26GB。
- 各範囲の中央タイルから開始し、その後周囲のタイルへ進む。ファイル名の番号は物理的な左→右の順序。

## 実行

まず中央の1タイル（2条件×4位相）でGPU動作と時間を確認：

```powershell
git pull
.\.venv\Scripts\python.exe scan_tiles.py --region center --limit-tiles 1 --spp 64
```

3範囲を一括で連続計算：

```powershell
.\.venv\Scripts\python.exe scan_tiles.py --spp 64
```

中央200mmだけを先に計算するなら`--region center`。対象範囲・分割・計算数だけ確認するなら`--plan-only`。GPUが使えないときは`--variant scalar_rgb`または`llvm_ad_rgb`。

## 計算法の変更と限界

従来の`simulate.py`は光源から光線を飛ばす`ptracer`。小さな撮影範囲だけにすると、そこへ届かない光線も多数計算する。局所スキャンでは受光面の画素側から追う`path`を使い、同じ形状・材質・光源を評価する。`simulate.py`自体の計算法は変更しない。

`path`は屈折・反射を追えるが、細い光路では依然として分散が大きい可能性がある。旧ptracerとの絶対値・収束の一致は未確認。sppは計算法が違えば同じ効率・同じ品質を意味しない。まず64sppで場所による特徴を見て、必要な場所で128・256sppや異なるseedの確認を行う。現在のCLIは設定JSONのrender.seedを使うため、別seedでは別設定ファイル・別出力先を使う。

GPUでは1回4spp（既定）ずつ手動で描画・平均し、総64sppを維持。メモリ不足なら`--samples-per-pass 1`。1回の画像は約52万画素で、4sppなら約210万の一次サンプル。RTX2080Ti実機での動作は未確認。

## 中断と再開

完了した各位相のNPYを保存する。Ctrl+Cで中断しても完了分は残る。中断中の1位相だけは次回やり直す。

元のオプションを同じにして、出力先を`--resume`で指定：

```powershell
.\.venv\Scripts\python.exe scan_tiles.py --spp 64 --resume results/scan_日時
```

`--region`、`--pixels`、`--samples-per-pass`などを変えていた場合は、それらも同じ値を指定する。設定が違う再開は拒否する。NPYの形状・有限値を確認して完了分をスキップする。

描画せず、保存済みの途中結果を解析する：

```powershell
.\.venv\Scripts\python.exe scan_tiles.py --analyze-only results/scan_日時
```

## 出力

| ファイル | 内容 |
|---|---|
| 各タイルの8個のNPY | 2048×256の線形照射分布。解析の原本 |
| 各タイルの8個のPNG | 同じ画素数の細かい画像。全タイル・全位相・全条件で共通色尺度 |
| 各タイルのfields.png | 2条件×4位相の一覧。表示は縮小されるため像幅は元NPYで測る |
| metrics.csv | 位相別の平均照射量、ピーク位置、基線を引いた主要ピークの推定半値幅、コントラスト |
| overlap.csv | 6組の位相間の規格化プロファイル重なり指標 |
| stitched_profiles.png | 連続画像を世界座標で並べた各範囲のプロファイル |
| comparison_metrics.png | 中央・端の幅と重なり指標の比較 |
| summary_bundle.zip | 最初に共有するためのCSV・全体比較図・設定。重いNPYは含めない |

個別PNGの表示上限は全ファイルの99.5百分位の最大値。突出した値を表示上クリップするが、元のNPYは変更しない。色の混合を使った量的な判断はしない。

主要ピークの推定幅は、局所プロファイルを約5周期分折り返し、σ=0.004mm（溝直角方向）で平滑化して求める。個々のレンズのPSFのFWHMや収差込みの厳密な像幅ではない。多峰性・ノイズ・近似周期が推定に影響する。低コントラストでは幅を空欄にする。

位相間重なりは、各プロファイルを積分1へ規格化し、`sum(min(Pi,Pj))`を計算する。0が非重複、1が同じ形状。明るさの差は規格化で消えるため、必ず平均照射量と併記する。暗い領域や低サンプルでは不安定。

**異位相は実機では別時刻に点灯するため、この指標は実機クロストーク率ではない。** LCDの左右画像割当、液晶応答、眼位置がモデルにないので、その漏れ率は算出しない。現在は照射像の重なりと場所による違いを比較する段階。

水平画素幅が0.01mmを超える縮小テストでは、ピーク位置・幅と重なりの数値を空欄にします（quality_flag=coarse_pixels）。既定の0.003906mm設定はこの制限に該当しませんが、収束検証済みという意味ではありません。
